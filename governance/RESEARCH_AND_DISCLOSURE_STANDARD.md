# Research, provenance and disclosure standard

A public research portfolio requires separating four things: (1) established research outputs, (2) independently verifiable professional experience, (3) implemented technical demonstrations, and (4) planned scientific or technical development.

## Before publication

- Confirm the researcher's actual contribution and the source supporting each claim.
- Inspect copyright, co-author rights, confidentiality and consent.
- Check whether repository history, example data, screenshots or exported metadata expose private information.
- Review claims of system capability against implementation state and independent tests.
- Mark synthetic data, speculative interpretations and provisional programme formulations explicitly.

## Methodological integrity

Document how a research question leads to its units of analysis, design, measurement, diagnostics and defensible inference. Report uncertainty and relevant sensitivity analyses. Examine alternative explanations. Use cultural-semiotic interpretation as part of problem construction and meaning analysis, with an explicit evidentiary basis.

## Application alignment

Interdisciplinary alignment requires a real scientific problem and credible methodological bridge. Avoid imitating job advertisements through vocabulary substitution. Keep tailored applications and unpublished proposal strategy in a private workspace.

## Disclosure boundary

Never import full text or code from private projects into this public repository without separate explicit disclosure review. Public-facing project profiles must be selective and attributable. The current repository carries no general reuse license; ask the rights holder before reusing its materials.
